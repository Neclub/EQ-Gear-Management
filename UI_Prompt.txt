## Python GUI entry (web_gui.py)

Pattern:
```python
import webview
from [package].web_api import WebApi
from [package].web_bridge import setup_url

def main() -> None:
    api = WebApi()
    window = webview.create_window(
        f"[APP NAME] v{__version__}",
        url=setup_url(),           # file:// path to setup.html
        js_api=api,                # exposes api methods to JS as pywebview.api.*
        width=860,
        height=640,
        min_size=(640, 480),
        background_color="#0b0e11",  # match --bg before HTML paints
    )
    api.bind_window(window)
    webview.start(debug=False)
```

## Python bridge (web_bridge.py)

- `setup_url()` → `Path(.../data/gui/setup.html).resolve().as_uri()`
- Optional `report_viewer_html(payload_json)` → read HTML template, inject JSON
  at a marker like `/*__REPORT_JSON__*/` so one template works for export AND
  in-app viewing
- Optional `logo_data_uri()` → base64-encode PNG for `<img src="...">` without
  file:// path issues

## Python API (web_api.py) — JS-callable methods

Create a `WebApi` class. Methods on this class become `pywebview.api.methodName()`
in JavaScript. Use plain Python types that serialize cleanly (dict, list, str,
int, bool, None).

Required patterns:

1. **Window binding**
   ```python
   def bind_window(self, window: webview.Window) -> None:
       self._window = window
   ```

2. **Native file dialogs** (use bound window)
   ```python
   def pick_folder(self) -> str | None:
       result = self._window.create_file_dialog(webview.FileDialog.FOLDER)
       return str(result[0]) if result else None

   def pick_output_file(self, suggested_name: str) -> str | None:
       result = self._window.create_file_dialog(
           webview.FileDialog.SAVE,
           directory=str(Path.home() / "Downloads"),
           save_filename=suggested_name,
           file_types=("Output (*.ext)", "All files (*.*)"),
       )
       ...
   ```

3. **Long-running work on a background thread** — never block the UI thread
   ```python
   def run_job(self, config: dict) -> dict:
       def work() -> None:
           try:
               result = self._run_job_sync(config)
               payload = json.dumps(result, ensure_ascii=False)
               self._window.evaluate_js(f"window.onJobComplete({payload})")
           except Exception as exc:
               err = json.dumps({"ok": False, "error": str(exc)})
               self._window.evaluate_js(f"window.onJobComplete({err})")
       threading.Thread(target=work, daemon=True).start()
       return {"ok": True, "started": True}
   ```

4. **Navigate between screens**
   ```python
   def navigate_to_setup(self) -> None:
       self._window.load_url(setup_url())

   def show_results(self, payload: dict) -> None:
       html = viewer_html(json.dumps(payload, ensure_ascii=False))
       self._window.load_html(html)
   ```

Implement these app-specific API methods (customize for your app):
- `get_version() -> dict`  — `{ "version": "...", "logoDataUri": "..." }`
- `[discover_inputs](folder: str) -> dict`
- `[run_main_action](config: dict) -> dict`  — starts background thread
- Any helper methods the setup page needs (validation, defaults, previews)

Keep domain logic in separate modules; WebApi should orchestrate and serialize.

## JavaScript front-end (setup.js)

Pattern:

```javascript
const state = { /* app state */ };
const $ = (id) => document.getElementById(id);

function api(method, ...args) {
  if (!window.pywebview?.api?.[method]) {
    return Promise.reject(new Error("App API not available."));
  }
  return Promise.resolve(pywebview.api[method](...args));
}

async function initApp() {
  const info = await api("get_version");
  $("versionBadge").textContent = `v${info.version}`;
  if (info.logoDataUri) $("logo").src = info.logoDataUri;
  bindEvents();
  refreshUI();
}

document.addEventListener("pywebviewready", initApp);
if (window.pywebview) initApp();  // already ready
```

Long job callback (Python calls this via evaluate_js):
```javascript
window.onJobComplete = async function (result) {
  setBusy(false);
  if (!result.ok) {
    showToast(result.error || "Failed.", true);
    return;
  }
  showToast("Done.");
  if (result.viewerPayload) await api("show_results", result.viewerPayload);
};
```

Use:
- Central `state` object + `refreshUI()` to re-render
- Toast notifications for success/error (auto-hide ~6s)
- Modal dialogs for help/about (inject HTML into `#modalRoot`)
- Disable controls while `generating` / busy

## Implementation rules

1. **No live server** — UI loads via file:// URLs; Python pushes HTML via
   `load_html()` when needed
2. **No blocking on UI thread** — file dialogs and quick lookups only on main
   thread; heavy work in daemon threads + `evaluate_js` callback
3. **JSON-safe API** — return dicts/lists from WebApi; never return Path objects
4. **Graceful degradation** — if `pywebview` not ready, show empty version badge;
   api() rejects with clear error
5. **Keep HTML readable** — no minification; separate .html / .css / .js files
6. **Match Inventory Parser UX feel** — dark, dense, panel-based, status footer,
   chip toggles, native folder/file pickers

## Deliverables

1. Working `run_gui.bat` that opens the setup screen
2. At least one end-to-end flow: pick input → configure options → run action →
   status toast → optional results viewer
3. `test_web_api.py` with meaningful coverage of WebApi helpers
4. Brief README section: requirements (WebView2), how to run GUI vs CLI

Do NOT use Tkinter, PyQt, Electron, or a JS framework. Follow the architecture
above closely so the new app feels identical in UI patterns to Inventory Parser.
